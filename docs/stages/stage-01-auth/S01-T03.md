# S01-T03 — تحسين رسائل الأخطاء في تسجيل الدخول والمصادقة لتكون موجهة للمستخدم النهائي وإخفاء رموز التتبع التقنية (`traceId`) وعبارات الخادم الداخلية

---

**اسم المهمة:** `S01-T03` — تحسين رسائل الأخطاء في تسجيل الدخول والمصادقة لتكون موجهة للمستخدم النهائي وإخفاء رموز التتبع التقنية (`traceId`) وعبارات الخادم الداخلية

**الهدف:** جعل جميع رسائل الأخطاء التي تظهر للمستخدم النهائي في شاشة تسجيل الدخول والمصادقة واضحة ومعبّرة ومكتوبة بلغة طبيعية احترافية، ومنع إظهار المصطلحات التقنية للخادم (مثل «خطأ داخلي في الخادم» أو «يرجى مراجعة معرف التتبع») أو إلحاق كود التتبع الطويل (`traceId` مثل `00-bbb6e3be...`) في نافذة الرسالة، مع بقاء الـ `traceId` في استجابة الشبكة (`JSON`) وسجلات الخادم لأغراض التشخيص التقني فقط.

**المخرج النهائي:**
1. تحديث شاشة تسجيل الدخول (`LoginPage.tsx`):
   - عدم إلحاق `traceId` بنص الرسالة المعروضة للمستخدم النهائي في `CentralModalDialog`.
   - استبدال أي رسالة خطأ خادم عامة (`500` أو تعذر الاتصال بالخادم) بعنوان ورسالة واضحين للمستخدم النهائي:
     - بالعربية: العنوان **«تعذر تسجيل الدخول حاليًا»**، والرسالة **«الخدمة غير متاحة مؤقتًا أو حدث خلل أثناء الاتصال. يرجى المحاولة مرة أخرى بعد قليل.»**
     - بالإنجليزية: العنوان **`Unable to Sign In Right Now`**، والرسالة **`The service is temporarily unavailable or a connection issue occurred. Please try again shortly.`**
2. تحديث النصوص الافتراضية لأخطاء `500` في الخادم (`ApiErrorLocalizer.cs`):
   - استبدال العنوان التقني «خطأ داخلي في الخادم» والرسالة التي تطلب مراجعة معرف التتبع بصياغة موجهة للمستخدم النهائي («تعذر إتمام العملية حاليًا» / «حدث خلل غير متوقع أثناء تنفيذ الطلب. يرجى المحاولة مرة أخرى بعد قليل.»)، مع الإبقاء على خاصية `traceId` داخل كائن `ProblemDetails` في JSON لضمان عدم تضرر أي اختبار آلي يفحص وجود حقل `traceId`.
3. ضمان تشغيل محرك `PostgreSQL` كعملية خلفية دائمة (`Daemon`) أثناء تشغيل التطبيق محليًا حتى لا ينقطع اتصال قاعدة البيانات أثناء الاختبار اليدوي.

**نطاق التنفيذ:**
- **المطلوب تنفيذه:**
  - تعديل `frontend/src/components/auth/LoginPage.tsx` لإزالة عرض `modalState.traceId` من نص `CentralModalDialog` وتخصيص رسالة واضحة للمستخدم النهائي عند حدوث خطأ غير متوقع أو تعذر الاتصال (`status >= 500` أو خطأ شبكة).
  - تعديل `backend/src/Shared/ApiGovernance.Shared/Contracts/ApiErrorLocalizer.cs` لتحسين النص الافتراضي لحالة `500` ليكون بلغة المستخدم النهائي دون ذكر «معرف التتبع» أو «خطأ داخلي في الخادم».
  - تحديث/إضافة تحقق في `frontend/src/__tests__/AuthFlow.test.tsx` يثبت أن أخطاء تسجيل الدخول تعرض رسالة المستخدم النهائي النظيفة دون إظهار كود `traceId` في نافذة الحوار.
- **ما لا يدخل ضمن المهمة:**
  - تعديل عقود `ProblemDetails` في الـ API أو حذف حقل `traceId` من استجابة الـ JSON (حفاظًا على عقود `F07` والاختبارات السابقة).
  - تعديل رسائل المراحل الأخرى خارج نطاق المصادقة والنص الافتراضي العام.

**معايير الاكتمال:**

- [x] عدم ظهور عبارة «خطأ داخلي في الخادم» أو «يرجى مراجعة معرف التتبع» للمستخدم النهائي، واستبدالها برسالة واضحة ومهنية باللغتين العربية والإنجليزية.
- [x] عمل محرك قاعدة البيانات والخادم والواجهة معًا بنجاح دون خطأ اتصال عند تسجيل الدخول.
