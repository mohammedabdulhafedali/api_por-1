# مواصفات المتطلبات المستهدفة
**الإصدار: 0.1 — مسودة هندسية للمراجعة، 27 نوفمبر 2026.** جميع القرارات الجديدة مقترحة وليست اعتماداً أو شهادة جاهزية. لا تعديل للتطبيق أو البيانات.
المتطلبات التفصيلية في 07_Functional_Requirements/REQUIREMENTS.csv ومصفوفة التتبع. الرمز P0 سلامة/أمن أو اعتماد، P1 وظيفة/UX. لا تعد هذه القائمة استبدالاً لمعرفات baseline غير المتاحة؛ يجب مصالحتها قبل التنفيذ.
## FR-01 — السجل المرجعي
إدارة أنظمة الشركة والمزود الداخلي كمرجع للنظام والمزود الخارجي والمستهلك وتصنيفه ومجموعات API؛ منع حذف مرتبط
- الشاشة: UI-REF؛ الوحدة: Reference؛ قبول: T01؛ الأولوية: P1.
## FR-02 — نوع الملف
تكوين الغرض الدلالي والنوع القياسي وقائمة الامتدادات وحد الحجم وحالة التفعيل؛ الامتداد المشتق read-only عند النوع القياسي
- الشاشة: UI-TYPE؛ الوحدة: Config؛ قبول: T02؛ الأولوية: P1.
## FR-03 — قالب المتطلبات
نسخ قالب بقواعد mandatory/optional/conditional وحد أدنى وأقصى لكل غرض؛ شرط من سياق معلوم لا كود حر
- الشاشة: UI-TPL؛ الوحدة: Config؛ قبول: T03؛ الأولوية: P1.
## FR-04 — مسار المراجعة
إدارة مراحل متسلسلة بأدوار وترتيب؛ رفض مسار فارغ عند التقديم؛ نسخ التهيئة على المرشح
- الشاشة: UI-ROUTE؛ الوحدة: Config؛ قبول: T04؛ الأولوية: P1.
## FR-05 — سياسات التغيير
ربط أنواع التغيير المسموح بها بالوثيقة ومسار موافقة وتحليل أثر؛ قوالب بإصدارات
- الشاشة: UI-CPOL؛ الوحدة: Config؛ قبول: T05؛ الأولوية: P1.
## FR-06 — المستخدم والأدوار
أدوار متعددة وإدارة حسابات وصلاحيات قابلة للمنح والسحب دون امتياز ثابت بسبب الاسم
- الشاشة: UI-USERS؛ الوحدة: Identity؛ قبول: T06؛ الأولوية: P0.
## FR-07 — صلاحيات فردية
أولوية REVOKE ثم GRANT الفردي ثم اتحاد الأدوار؛ عدم حذف قاموس الصلاحيات
- الشاشة: UI-USERACL؛ الوحدة: Identity؛ قبول: T07؛ الأولوية: P0.
## FR-08 — وثائق API
تسجيل علاقة مزود/مستهلك ومجموعة وقالب ومسار وسياسة؛ عنوان مشتق وقواعد تفرد معتمدة
- الشاشة: UI-DOC؛ الوحدة: Documents؛ قبول: T08؛ الأولوية: P1.
## FR-09 — ACL الوثيقة
استثناء فردي صريح ثم سحب دور ثم منح دور؛ تطبيق الإذن العام والوثيقة والسياق معاً
- الشاشة: UI-DOCACL؛ الوحدة: Documents؛ قبول: T09؛ الأولوية: P0.
## FR-10 — تكامل
تكامل واحد لكل وثيقة؛ مطورون معيّنون دون منح صلاحية تلقائياً
- الشاشة: UI-INT؛ الوحدة: Integrations؛ قبول: T10؛ الأولوية: P0.
## FR-11 — إصدار API
مطور مخول يختار رقم نصي يدوي فريد؛ لا ترقية فنية داخل المنصة؛ فصل إصدار API عن مراجعة التوثيق
- الشاشة: UI-VERS؛ الوحدة: VersionsFiles؛ قبول: T11؛ الأولوية: P0.
## FR-12 — مسودة
إنشاء مراجعة توثيق مرتبطة بإصدار ونسخة أساس؛ مسودة نشطة واحدة لكل إصدار كمقترح؛ تعارض 409
- الشاشة: UI-FILES؛ الوحدة: VersionsFiles؛ قبول: T12؛ الأولوية: P0.
## FR-13 — رفع
رفع متعدد الأغراض وفق قالب؛ التحقق خادمي من الحجم والامتداد والمحتوى؛ معرف تخزين عشوائي وبصمة SHA-256
- الشاشة: UI-FILES؛ الوحدة: VersionsFiles؛ قبول: T13؛ الأولوية: P0.
## FR-14 — الفحص
PENDING_SCAN لا معاينة أو تنزيل؛ CLEAN بعد نتيجة إيجابية حقيقية؛ خطأ/تعطل يبقي الحظر؛ إعادة محكومة للفحص
- الشاشة: UI-FILES؛ الوحدة: SecurityScan؛ قبول: T14؛ الأولوية: P0.
## FR-15 — اكتمال
الحدود والشرط والمطابقة للغرض والتحقق الدلالي البشري؛ كل ملف مدرج CLEAN قبل التقديم
- الشاشة: UI-FILES؛ الوحدة: VersionsFiles؛ قبول: T15؛ الأولوية: P0.
## FR-16 — تجميد
التقديم ينشئ manifest غير قابل للتعديل مع hash للقائمة وتهيئة مثبتة؛ موافقات على manifest محدد
- الشاشة: UI-REVIEW؛ الوحدة: Workflow؛ قبول: T16؛ الأولوية: P0.
## FR-17 — صندوق مهام
تعرض المهمات النشطة للمخول والمعيّن أو آلية الدور المعتمدة؛ فحص الصلاحية عند التنفيذ
- الشاشة: UI-INBOX؛ الوحدة: Workflow؛ قبول: T17؛ الأولوية: P0.
## FR-18 — ملاحظات
تعليق مرتبط بمرشح وملف/موضع اختياري، درجة إلزام، رد، دليل، إغلاق مخول؛ سجل غير مطموس
- الشاشة: UI-REVIEW؛ الوحدة: Workflow؛ قبول: T18؛ الأولوية: P1.
## FR-19 — قرار مرحلة
Approve/Return/Reject مع سبب للإرجاع والرفض؛ يمنع القرار المكرر والتزامن؛ لا انتقال بلا إذن
- الشاشة: UI-REVIEW؛ الوحدة: Workflow؛ قبول: T19؛ الأولوية: P0.
## FR-20 — إعادة التقديم
إرجاع ينشئ مسودة مشتقة؛ يحفظ المرشح السابق؛ إعادة كل الموافقات عند تعديل الحزمة وفق ADR-P05
- الشاشة: UI-FILES؛ الوحدة: Workflow؛ قبول: T20؛ الأولوية: P0.
## FR-21 — الاعتماد
اكتمال المراحل الإلزامية وعدم وجود ملاحظات مانعة؛ قرار حزمة غير قابل للتغيير؛ شهادة مستقلة قابلة للتحقق
- الشاشة: UI-REVIEW؛ الوحدة: Workflow؛ قبول: T21؛ الأولوية: P0.
## FR-22 — Word
تعبئة حقول معروفة قبل التجميد فقط في مشتق مفحوص؛ لا تعديل signed/encrypted/unmapped؛ إثبات جدوى
- الشاشة: UI-FILES؛ الوحدة: DocumentProcessing؛ قبول: T22؛ الأولوية: P1.
## FR-23 — طلب التغيير
المطور المخول يقدم نوعاً وسبباً ونطاق ملفات وأثر API؛ الموافقة تتيح نسخة عمل فقط
- الشاشة: UI-CHANGE؛ الوحدة: Changes؛ قبول: T23؛ الأولوية: P0.
## FR-24 — تنفيذ التغيير
تغيير API الفني خارج النظام؛ المطور يربط رقم الإصدار الجديد ودليل الاختبار أو مراجعة ضمن الإصدار حسب التصنيف
- الشاشة: UI-CHANGE؛ الوحدة: Changes؛ قبول: T24؛ الأولوية: P0.
## FR-25 — النشر
مسؤول مخول ينشر ملفات CLEAN من manifest المعتمد إلى جمهور محدد؛ معاملة ذرية؛ عدم استبدال ضمني
- الشاشة: UI-PUB؛ الوحدة: Publishing؛ قبول: T25؛ الأولوية: P0.
## FR-26 — البوابة
قائمة وتنزيل منشور فقط بعد ACL والجمهور والصلاحيات والحالة؛ لا روابط تخزين عامة
- الشاشة: UI-PORTAL؛ الوحدة: Publishing؛ قبول: T26؛ الأولوية: P0.
## FR-27 — البحث
بحث وتصفية بعد قيد الوصول قبل العد والترقيم؛ لا تسريب وجود سجلات غير مخولة
- الشاشة: UI-SEARCH؛ الوحدة: Documents؛ قبول: T27؛ الأولوية: P0.
## FR-28 — التدقيق
أحداث actor/action/object/manifest/time/result/correlation بدون أسرار؛ append-only منطقي
- الشاشة: UI-AUDIT؛ الوحدة: Audit؛ قبول: T28؛ الأولوية: P0.
## FR-29 — الإشعارات
إشعار مهمة/إرجاع/اعتماد/نشر عبر outbox مع إعادة محاولة وعدم تكرار منطقي؛ لا محتوى حساس
- الشاشة: UI-NOTIFY؛ الوحدة: Notifications؛ قبول: T29؛ الأولوية: P1.
## FR-30 — التشغيل
أرشفة وإيقاف نشر بإذن وسبب؛ منع حذف المعتمد؛ retention/legal hold وفق سياسة معتمدة
- الشاشة: UI-PUB؛ الوحدة: Publishing؛ قبول: T30؛ الأولوية: P1.
## FR-31 — الواجهة
مرجع HTML، صفحات إضافة وتعديل مستقلة، حوارات مركزية، AR/EN RTL/LTR والثيمان؛ لا UI-XX للمستخدم
- الشاشة: ALL؛ الوحدة: Frontend؛ قبول: T31؛ الأولوية: P1.
## FR-32 — لوحة التحكم
مؤشرات حقيقية وصندوق حالات عمل ومهام ونشاط مصفاة بالصلاحيات؛ لا بيانات تجريبية في الإنتاج
- الشاشة: UI-DASH؛ الوحدة: Frontend؛ قبول: T32؛ الأولوية: P1.
## FR-33 — مصادقة
جلسات حقيقية وHttpOnly وسياسة CSRF وتهيئة أول مدير محلياً؛ لا سر ثابت؛ تعطيل يوقف الجلسة وفق قرار معتمد
- الشاشة: UI-LOGIN؛ الوحدة: Identity؛ قبول: T33؛ الأولوية: P0.
## FR-34 — تنزيل ومقارنة
تنزيل مخول مع تدقيق؛ فرق أسماء/بصمات/محتوى نصي آمن عند الدعم؛ لا ادعاء مقارنة ثنائية كاملة
- الشاشة: UI-FILES؛ الوحدة: VersionsFiles؛ قبول: T34؛ الأولوية: P1.
