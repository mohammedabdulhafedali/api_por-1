# التصميم المستهدف — منطق النظام
**الإصدار: 0.1 — مسودة هندسية للمراجعة، 27 نوفمبر 2026.** جميع القرارات الجديدة مقترحة وليست اعتماداً أو شهادة جاهزية. لا تعديل للتطبيق أو البيانات.
## الكيانات والحدود
DocumentRegistration يصف العلاقة، Integration يدير دورة التوثيق 1:1، ApiVersion رقم يدوي داخل Integration، DocRevision رقم تسلسلي ضمن ApiVersion، FileBlob مخزن خاص غير قابل للتغيير، RevisionFile يربط غرضاً بنسخة ملف، Manifest يثبت محتويات المرشح، WorkflowInstance يثبت المراحل، ReviewTask/Decision/Comment تحفظ القرارات، ChangeRequest ينظم الانتقال من أصل معتمد إلى عمل جديد، Publication يربط مجموعة فرعية وجمهوراً. لا تستخدم status واحداً لجميع الكيانات.
## بوابات القرار
1. **إنشاء**: مرجع فعال، إذن عام، ACL عند سجل موجود، تعيين سياقي، تفرد.
2. **الرفع**: مسودة نشطة، نوع وغرض مسموح، تحقق حجم/بنية، تخزين حجر، hash، مهمة فحص. لا تنزيل حتى CLEAN.
3. **التقديم**: كل الملفات المدرجة CLEAN، تحقق min/max والشروط، مسار صالح؛ معاملة واحدة تثبت snapshot وmanifest وتفتح مهمة المرحلة الأولى.
4. **المراجعة**: تحقق الصلاحية الحالية والتعيين وحالة المرحلة وETag؛ الملاحظات المانعة تمنع الموافقة. Return/Reject يحفظ المرشح، لا تحرير. إعادة التقديم بعد تصحيح تبدأ مرشحاً جديداً وموافقات جديدة وفق المقترح.
5. **الاعتماد**: اكتمال آخر مرحلة؛ حفظ قرارات مرتبطة بـmanifest؛ توليد شهادة منفصلة لا تغيّر الملفات. إذا تتطلب الجهة اعتماداً نهائياً يكون مرحلة صريحة.
6. **التغيير**: طلب نوع وأثر، تقييم واعتماد الطلب، نسخة عمل منفصلة؛ فني خارج النظام؛ إعادة توثيق ومراجعة ثم نشر اختياري.
7. **النشر**: ملفات نظيفة من الحزمة المعتمدة، جمهور مخول، قرار نشر مستقل؛ منع ملفات داخلية غير مختارة؛ سحب/حجب بإذن وسبب.
## المعاملات والاتساق
DB transaction لتقديم أو قرار أو نشر، unique constraints للتفرد، optimistic concurrency/ETag، idempotency لكل عملية حساسة. تخزين الملف والمعاملة لا يدعيان atomicity مشتركة: staging ثم ربط/اعتماد DB، عامل reconcile ينظف الأيتام وفق سياسة، لا إدراج ملف غير مكتمل. Outbox في المعاملة للمهام والإشعارات. الوقت UTC من الخادم؛ عرض محلي. لا يكتب النظام اسم معتمد مستقبلي في ملف.
## واجهات التنفيذ
راجع SCREEN_INVENTORY وAPI_PROPOSED.json وDATA_DICTIONARY.csv وSTATE_TRANSITIONS.csv. مواصفات API نموذج مستهدف تحتاج مطابقة فعلية مع catalog المشروع. سجل الحالات مستقل. النموذج التفاعلي لتفسير workflow وليس دليل اختبار إنتاجي.
## ما يحتاج اعتماداً
المسار النهائي، فصل الواجبات، السياسة الدقيقة للتصحيح، قواعد conditional، صلاحية الشهادة، مدة الاحتفاظ، جمهور النشر والتعايش، حدود الأداء، وPoC Word. حتى حسمها لا تعتمد baseline جديداً.
