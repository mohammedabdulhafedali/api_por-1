# التحديات والحلول الموصى بها
**الإصدار: 0.1 — مسودة هندسية للمراجعة، 27 نوفمبر 2026.** جميع القرارات الجديدة مقترحة وليست اعتماداً أو شهادة جاهزية. لا تعديل للتطبيق أو البيانات.
| المشكلة | الخيارات | الاختيار المقترح والسبب | أثره |
|---|---|---|---|
| صيغ وملفات مختلفة | نوع واحد / قالب ثابت / قالب ديناميكي | فصل format عن purpose، قالب بإصدارات وmin/max/conditional؛ لا تعديلات برمجية لكل غرض | FR-02/03/15، Config، شاشة بطاقات |
| ماذا نعتمد؟ | ملف / حزمة / كلاهما | قرارات وملاحظات على الملف، اعتماد نهائي للحزمة ذات manifest ثابت؛ اتساق عبر الملفات | FR-16/18/21 |
| الكتابة على Word | يدوي / آلي / هجين / فصل كامل | الفصل الكامل افتراضياً لجميع الصيغ، هجين اختياري للحقول قبل التجميد؛ شهادة مستقلة بعد الاعتماد | FR-22، PoC |
| أكثر من معتمد | تسلسلي / متوازٍ / quorum | حافظ على المتسلسل، قرار مؤهل واحد لكل مرحلة كـMVP؛ لا معتمد نهائي مستقل بلا مسؤولية جديدة | FR-04/19/21 |
| إرجاع الملف | تعديل المرشح / نسخة عمل / اعتماد جزئي | نسخة مشتقة جديدة؛ إعادة المراحل عند تعديل البايتات. أكبر تكلفة مراجعة لكن أدلة أوضح | FR-20 |
| الملاحظات | تعديل الملف داخل المنصة / تنزيل / تعليقات خارجية | ملاحظات منظمة داخل النظام، تنزيل آمن؛ ملف تعليقات منفصل عند الحاجة | FR-18/34 |
| تغيير بسيط بعد الاعتماد | overwrite / إصدار API / مراجعة | مراجعة توثيق جديدة من طلب مبسط، نفس إصدار API | CH-02 |
| تغيير فني | كل تغيير إصدار / بلا إصدار / سياسة | المطور يحدد إصداراً بحسب العقد والسياسة؛ تغيير كاسر يحتاج إصداراً جديداً وفق التوصية | CH-05/06 |
| قوالب تتغير | تعديل رجعي / snapshots | لقطة نسخة مثبتة في المرشح | ADR-P08 |
| تعطل scanner | السماح / حجر | Fail-closed؛ pending ثم فحص حقيقي | FR-14 |
| التعارض | last write wins / lock / optimistic | ETag + قيد فريد؛ معاملتان لا تنتجان قرارين | FR-12/19 |
| التسريب | روابط مباشرة / API مخول | تخزين خاص ومعرفات opaque وACL عند كل طلب | FR-26 |
| الاستعادة | DB فقط / DB+storage | نقطة متسقة مع manifest ومراجعة hashes واختبار restore | NFR-06 |
| تغيير المستخدم | snapshot الأشخاص / صلاحيات آنية | ثبت المرحلة والدور لا حق المستخدم؛ تحقق الإذن والتعيين وقت التنفيذ | FR-17/19 |

البدائل الأكثر تعقيداً (محرر Office داخل الموقع، اعتماد جزئي لملف، quorum أو محرك عام، مقارنة ثنائية شاملة، توقيع رقمي مؤهل) ليست افتراض MVP. تحتاج حاجة مثبتة وتجربة وتكلفة واعتماداً منفصلاً.
