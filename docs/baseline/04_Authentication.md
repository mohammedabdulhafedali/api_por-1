# AUTH-01 — الحسابات المحلية والعقود v1.2

**معتمد:** ASP.NET Core Identity لحسابات التطبيق المحلية؛ قابلية إضافة هوية مؤسسية مستقبلًا. **التفاصيل التالية تصميم تنفيذ مقترح يجب مراجعته ضمن I01؛ لا كود منفذ.** لا تسجيل ذاتي ولا افتراض SMTP أو Active Directory.

## نموذج الهوية والجلسات
- معرف المستخدم UUID ثابت مرتبط بسجل `users` وقابل للربط بمصدر هوية مستقبلي. البريد الفريد الحالي يستخدم كمعرف الدخول (تصميم مبدئي؛ يمكن دعم اسم مستخدم مستقل إن تقرر). لا أدوار موازية متعارضة بين Identity وقاموس المنصة؛ عضوية `user_roles` هي المصدر الحاكم للتفويض.
- Identity يدير تجزئة كلمات المرور وتحديثها والتحقق منها والحماية من تكرار المحاولات. لا تخزين كلمات مرور نصية أو في السجل. تعطيل الحساب والخروج وتغيير كلمة المرور/إعادة تعيينها يبطل الجلسات المعنية. الواجهة والخادم على origin واحد؛ جلسة Cookie محمية Secure وHttpOnly وSameSite مع تحقق CSRF لكل طلب تغيير بما فيه تسجيل الدخول. تصميم مخزن تذاكر خادمي قابل للإبطال؛ حفظ مفاتيح Data Protection خارج المستودع.
- كل عملية حساسة تتحقق من الحساب النشط والصلاحيات الفعلية الحالية؛ لا اعتماد على أدوار قديمة في Cookie. لا حفظ أسرار في LocalStorage. `GET /me` يعيد المعرف والاسم والأدوار والصلاحيات العامة ونطاق الجهة دون أسرار؛ لا يعتبر مصدر قرار الخادم.

## عقود الخدمات — إضافات إلى الـ93
| Method | Path | المدخل | المخرج/الشرط |
|---|---|---|---|
| GET | `/api/v1/auth/csrf` | لا شيء | 200 رمز طلب antiforgery؛ no-store؛ للاستخدام ضمن origin نفسه |
| POST | `/api/v1/auth/login` | email,password + CSRF | 200 ملخص الحساب، Cookie جلسة جديدة، 401 رسالة موحدة عند فشل الدخول، 429 عند تجاوز الحد |
| POST | `/api/v1/auth/logout` | جلسة + CSRF | 204 إبطال التذكرة على الخادم وإزالة Cookie |
| GET | `/api/v1/me` | جلسة | 200 ملخص الهوية؛ موجود سابقًا ولا يكرر |
| POST | `/api/v1/auth/password/change` | currentPassword,newPassword + جلسة + CSRF | 204 تغيير وإبطال الجلسات وإعادة الدخول |
| POST | `/api/v1/users/{userId}/password/reset` | إذن صريح `users.password.reset` + CSRF | 204 بدء مسار تسليم رمز أحادي الاستخدام عبر قناة معتمدة، لا كلمة مرور ولا رمز في الرد الإداري المعتاد |
| POST | `/api/v1/auth/password/reset/complete` | email,token,newPassword + CSRF | 204 تعيين كلمة مرور وإبطال الرمز والجلسات؛ رسالة عامة عند الفشل |

**التفعيل الأول:** يستخدم مسار إعادة التعيين نفسه للحساب الجديد؛ لا حساب قابل للدخول قبل تفعيل كلمة مرور بواسطة صاحبه. لا يُفتح التسجيل الذاتي. قناة تسليم رمز موثقة وآمنة (خارج الإشعارات العامة؛ لا إرسال بريد مفترض) شرط قبل إغلاق I01؛ لا تنفذ إعادة تعيين شكلية. الرمز محدد الغرض والمدة وأحادي الاستخدام؛ تمنع إعادة التشغيل والتخمين، ويحجب من السجلات. يلزم اعتماد آلية التحقق من هوية المستلم وتسليم الرمز في المؤسسة. لا يغير هذا القرار المحلي المعتمد.

## الحدود والمعايير
- `400` مدخل غير سليم؛ `401` جلسة غائبة/باطلة؛ `403` إجراء ممنوع؛ `404` مورد غير مرئي حسب سياسة منع الكشف؛ `429` تجاوز المحاولات؛ `500` رسالة عامة وtraceId. لا تحويل HTML في API.
- سياسة كلمة المرور، مدد الجلسة والرمز، القفل، والإجراء عند تعذر تسليم الرمز: قرارات تشغيلية قبل I01، لا أرقام مخترعة. تُسجل عمليات الدخول والخروج والفشل والتفعيل والتغيير دون بيانات سرية.
- منع الوصول إلى مستندات جهات أخرى حتى بتغيير المعرف؛ اختبارات تفويض مستقلة عن نجاح المصادقة.
