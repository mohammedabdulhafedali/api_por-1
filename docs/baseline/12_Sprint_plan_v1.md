# خطة السبرنتات — منصة حوكمة وثائق APIs والتكاملات

**الإصدار:** 1.0 — تخطيط المرحلة السادسة (لم يبدأ تنفيذ أي سبرنت).

**المكدس المعتمد:** React 19 + TypeScript / ASP.NET Core 10 LTS / PostgreSQL 18 / EF Core 10 / Open XML SDK / Windows Server + IIS.

**النطاق:** جميع المهام الـ59 دون إضافة أو إسقاط، موزعة على 14 سبرنتًا متسلسلًا مع التزام التبعيات.

**الإطار الزمني المقترح:** أسبوعان لكل سبرنت كحد تخطيطي مبدئي فقط، وتُراجع السعة بعد السبرنت الأول. لا توجد تواريخ إنجاز معتمدة.

## التفاصيل وشروط إغلاق كل سبرنت

### S01 — تأسيس بيئة تطوير قابلة للتشغيل
**المخرج:** واجهة React وخادم ASP.NET Core يعملان محليًا، عقود API، اختبارات أولية وهوية UI.

- **F01** — إعداد المستودع وفروع العمل وREADME. **التبعيات:** لا توجد.
- **F02** — تهيئة React 19 وTypeScript وقالب الصفحة. **التبعيات:** F01.
- **F03** — تهيئة ASP.NET Core 10 بوحدات داخلية. **التبعيات:** F01.
- **F07** — وضع معيار عقود API والأخطاء والنسخ والتوثيق. **التبعيات:** F03.
- **F06** — تأسيس اختبارات الخادم والواجهة وخط فحص آلي. **التبعيات:** F02، F03.
- **F08** — إعداد هيكل UI المشترك والهوية البصرية. **التبعيات:** F02.

**بوابة القبول:** نجاح build وhealth endpoint وlint/test الأولي، دون أسرار أو وظائف وهمية. ويشترط توثيق نتائج البناء والاختبارات والمراجعة وأي مخاطر مفتوحة.

### S02 — قاعدة البيانات والمصادقة والمستخدمون
**المخرج:** PostgreSQL وEF Core والترحيلات، جلسات موثقة، إدارة مستخدمين.

- **F04** — ربط PostgreSQL 18 بـ EF Core 10 وNpgsql. **التبعيات:** F03.
- **F05** — إنشاء ترحيلات البنية الأساسية بعد مطابقة نموذج البيانات المعتمد. **التبعيات:** F04.
- **I01** — طبقة هوية وجلسة بخيار موفر هوية قابل للتبديل. **التبعيات:** F04، F07.
- **I02** — إدارة المستخدمين وحالات التفعيل. **التبعيات:** I01، F05.

**بوابة القبول:** migration وrollback في بيئة اختبار، رفض غير الموثق، تعطيل الحساب يمنع الوصول. ويشترط توثيق نتائج البناء والاختبارات والمراجعة وأي مخاطر مفتوحة.

### S03 — الأدوار المتعددة والصلاحيات العامة
**المخرج:** مصفوفة صلاحيات شاملة، أدوار متعددة، منح وسحب فردي، تفويض خادم.

- **I03** — إسناد أدوار متعددة للمستخدم. **التبعيات:** I02.
- **I04** — مصفوفة صلاحيات الدور ومنح/سحب الفرد. **التبعيات:** I03.
- **I05** — مكون تفويض خادم مركزي لكل API. **التبعيات:** I04، F07.
- **I06** — مصفوفة الأدوار والمستخدمين في React. **التبعيات:** I04، F08.

**بوابة القبول:** اختبارات اتحاد الأدوار وسحب الموروث، منع تجاوز الواجهة وتحقق 403. ويشترط توثيق نتائج البناء والاختبارات والمراجعة وأي مخاطر مفتوحة.

### S04 — سجلات الأنظمة والجهات والمزودين
**المخرج:** تعريف أنظمة الشركة والمزودين والجهات ومجموعات API وأنواع الملفات.

- **M01** — أنظمة الشركة وأنواع استخدامها المحسوبة. **التبعيات:** F05، I05.
- **M02** — المزودون الداخليون والخارجيون. **التبعيات:** M01.
- **M03** — تصنيفات الجهات المستهلكة والجهات. **التبعيات:** F05، I05.
- **M04** — مجموعات API وقاموس أنواع الملفات. **التبعيات:** F05، I05.

**بوابة القبول:** حماية المراجع، منع تكرار النظام الداخلي، تحقق الامتدادات وتصنيف الأنظمة المحسوب. ويشترط توثيق نتائج البناء والاختبارات والمراجعة وأي مخاطر مفتوحة.

### S05 — قواعد التهيئة ومسارات الاعتماد
**المخرج:** قوالب متطلبات الملفات، مراحل مرتبة حسب الدور، أنواع طلبات التغيير.

- **M05** — قوالب متطلبات الملفات مع لقطات تاريخية. **التبعيات:** M04.
- **M06** — مسارات اعتماد: اسم المرحلة وترتيبها ودورها. **التبعيات:** I03.
- **M07** — أنواع طلبات التغيير وربطها بالمسارات. **التبعيات:** M06.

**بوابة القبول:** حفظ لقطة إعدادات، منع مسار غير صالح، عدم وجود نوع مرحلة أو تعيين مستخدم إلزامي. ويشترط توثيق نتائج البناء والاختبارات والمراجعة وأي مخاطر مفتوحة.

### S06 — وثائق API وصلاحيات كل وثيقة
**المخرج:** إنشاء الوثيقة وتعيين مطوريها، ACL منفصل، ربط تكامل واحد بالوثيقة.

- **D01** — إنشاء وثيقة API بعلاقات المزود والمستهلك والمجموعة. **التبعيات:** M02، M03، M04، M05، M06، M07، I05.
- **D02** — تعيين المطورين للوثيقة عند إنشائها. **التبعيات:** D01، I03.
- **I07** — إدارة الوصول إلى الوثيقة بمستخدميها وأدوارها. **التبعيات:** I05، D02.
- **D03** — قائمة وتعديل الوثائق وحماية الحذف. **التبعيات:** D01، I07.
- **D04** — إنشاء تكامل مرتبط بالوثيقة 1:1. **التبعيات:** D01، I07.
- **U02** — مصفوفة صلاحيات المستخدم والوثيقة بجميع الإجراءات. **التبعيات:** I06، I07.

**بوابة القبول:** منع الحذف بعد الربط، وثيقة مقيدة افتراضيًا، منع IDOR، المصفوفة ظاهرة كاملة. ويشترط توثيق نتائج البناء والاختبارات والمراجعة وأي مخاطر مفتوحة.

### S07 — شاشات التكامل والمستخدمين وتجربة العمل
**المخرج:** تعيين مطوري التكامل، شاشات التفاصيل، ترجمة وتوحيد الرسائل والنماذج.

- **D05** — تعيين مطورين للتكامل وإدارة النطاق. **التبعيات:** D04، I03.
- **D06** — قائمة وتفاصيل التكامل وتبويباته. **التبعيات:** D04، F08.
- **U01** — تعريب/إنجليزية لكل شاشات الأعمال ورسائلها. **التبعيات:** F08، D06.
- **U03** — الرسائل المنبثقة وصفحات الإضافة المستقلة. **التبعيات:** F08، D06.

**بوابة القبول:** صفحات إضافة/تعديل مستقلة، لغة RTL/LTR، لا تسرب بيانات غير مصرح بها. ويشترط توثيق نتائج البناء والاختبارات والمراجعة وأي مخاطر مفتوحة.

### S08 — تخزين الملفات والفحص وإنشاء الإصدار
**المخرج:** تخزين خاص ثابت، رفع وفحص الملفات، إدخال رقم إصدار API يدويًا.

- **V01** — كائن ملف ثابت وواجهة مخزن خاص. **التبعيات:** F05، I05.
- **V02** — رفع محجور والتحقق من الأنواع والأحجام. **التبعيات:** V01، M04.
- **V03** — ربط فاحص الملفات وتعامل الفشل الآمن. **التبعيات:** V02.
- **V04** — إنشاء إصدار API برقم نصي يدوي. **التبعيات:** D04.

**بوابة القبول:** رفض ملف مخالف أو غير مفحوص، بصمة ثابتة، قبول نص حر للإصدار. ويشترط توثيق نتائج البناء والاختبارات والمراجعة وأي مخاطر مفتوحة.

### S09 — حزم التوثيق وحماية النسخ وتجربة Word
**المخرج:** اكتمال الملفات المطلوبة، النسخ غير القابلة للاستبدال، تنزيل مرخص، إثبات Word.

- **V05** — مراجعات حزمة توثيق وإلزامية الملفات. **التبعيات:** V03، V04، M05.
- **V06** — منع تعديل المعتمد وإنشاء نسخة عمل. **التبعيات:** V05.
- **V07** — تحميل الملفات عبر الخادم مع تدقيق. **التبعيات:** V01، I07.
- **V08** — إثبات جدوى تحديث Word بقوالب مختلفة. **التبعيات:** V05.

**بوابة القبول:** منع إرسال الناقص وتعديل المعتمد، فحص بصمة التنزيل، تقرير إثبات Word غير معمم. ويشترط توثيق نتائج البناء والاختبارات والمراجعة وأي مخاطر مفتوحة.

### S10 — الاعتماد المتسلسل للمستندات
**المخرج:** تشغيل المسارات وقرارات الأعضاء المؤهلين والانتقال والإعادة/الرفض.

- **W01** — إنشاء تشغيل مسار من لقطة مراحله. **التبعيات:** M06، V05، I05.
- **W02** — أهلية عضو الدور واتخاذ قرار ذري. **التبعيات:** W01، I04، I07.
- **W03** — انتقال المراحل وإكمال آخر مرحلة. **التبعيات:** W02.
- **W04** — إعادة العمل وملاحظات الرفض والسجل. **التبعيات:** W03، V06.

**بوابة القبول:** قرار واحد لكل مرحلة، آخر مرحلة تكمل المسار، بقاء السجل وحفظ الملاحظات. ويشترط توثيق نتائج البناء والاختبارات والمراجعة وأي مخاطر مفتوحة.

### S11 — طلبات التغيير والإشعارات
**المخرج:** طلب تغيير مقيد بالملفات المتأثرة، اعتماد مستقل، إشعارات من أحداث مسار العمل.

- **W06** — اعتماد طلب التغيير بمسار مستقل. **التبعيات:** W02، W05.
- **W07** — إشعارات داخلية من أحداث المراحل. **التبعيات:** W03، W06.

**بوابة القبول:** لا تعديل خارج نطاق الطلب، ولا يكفي اعتماد الطلب لاعتماد الوثائق؛ لا تكرار للإشعار. ويشترط توثيق نتائج البناء والاختبارات والمراجعة وأي مخاطر مفتوحة.

**بوابة القبول:** حجب المسودات، عزل جهات الاستهلاك، تنزيل المسموح فقط وإيقاف فوري. ويشترط توثيق نتائج البناء والاختبارات والمراجعة وأي مخاطر مفتوحة.

### S13 — التدقيق وتجربة المستخدم واختبارات التكامل
**المخرج:** بحث وتدقيق ولوحة التحكم، واجهة متجاوبة، اختبارات تفويض ودورة عمل كاملة.

**بوابة القبول:** دورة كاملة ناجحة، اختبار IDOR، سيناريو طلب تغيير، تجربة هاتف/ثيمين. ويشترط توثيق نتائج البناء والاختبارات والمراجعة وأي مخاطر مفتوحة.

## بوابات الجودة الأساسية

- **B0 — قبل S01:** اعتماد مراجع المشروع، وعدم استخدام بيانات أو خدمات إنتاجية للتجربة، ومعالجة قرارات الأمن المؤثرة أو إعلان افتراضات واضحة.
- **B1 — بعد S02:** تشغيل الواجهة والخادم محليًا مع قاعدة بيانات اختبار، وفحص البناء والترحيلات والتراجع.
- **B2 — بعد S06:** تحقق الصلاحيات العامة والفردية وعلى مستوى الوثيقة داخل الخادم، بما فيها حالات الرفض والتجاوز.
- **B3 — بعد S12:** نجاح دورة الوثيقة ← التكامل ← الإصدار ← الرفع ← المراجعة ← الاعتماد ← النشر، ودورة طلب تغيير معتمدة.
- **B4 — بعد S14:** استكمال نتائج اختبارات الاستعادة والأمان والأداء وUAT ومراجعة جاهزية النشر مع IT.

## طريقة إدارة كل سبرنت

1. مراجعة التبعيات واختيار المهام المدرجة تحت السبرنت فقط.
2. إسناد كل مهمة لوكيل تطوير وإسناد مراجعتها لوكيل آخر إن أمكن.
3. تسليم المهمة مع ملف المتطلبات ومعرفها ومعيار قبولها والمخرجات المتوقعة.
4. الحصول على تقرير التغييرات، أوامر البناء والاختبار ونتائجها، والأدلة.
5. إجراء مراجعة قبول للسبرنت وتحديث حالة كل مهمة في جدول المتابعة.
6. عدم الانتقال للسبرنت التالي بوجود عائق حرج غير محسوم.

## قرارات وحدود تحتاج المتابعة

- تظل مسؤولية تجهيز Windows Server وIIS وشبكات المؤسسة والنسخ الاحتياطي والتخزين وقواعد الوصول لدى **IT**.
- لا تُحوَّل صفحة HTML المرجعية إلى تطبيق إنتاجي مباشرة؛ يُبنى تطبيق React/ASP.NET Core وفق المواصفات.
- يجب إجراء إثبات جدوى عملي لمعالجة Word على مستندات موحدة وغير موحدة، دون الادعاء بإمكانية تعديل كل قالب.
- لا تُحذف الصلاحيات من النظام؛ تدار بمنح وسحب، مع دعم الأدوار المتعددة واستثناءات المستخدم وصلاحيات كل وثيقة.
- السبرنتات ليست موافقات على تنفيذ تغييرات إنتاجية، ويظل النشر والانتقال للإنتاج خاضعين لاعتماد منفصل.

## الخطوة التالية

اجتياز بوابة **B0**، ثم بدء **S01** بالمهمة **F01** عند تفويض البرمجة. بعد إقرار خطة السبرنتات تُراجع حزمة المرحلة السابعة للتحقق من التتبع والجاهزية.
